# Debugging

버그, 테스트 실패, 빌드 실패, 예기치 않은 동작은 원인 확인 후 수정합니다.

## 4단계

### 1. 원인 조사

- 오류 메시지와 스택 트레이스를 끝까지 읽습니다.
- 재현 절차를 확인합니다.
- 최근 변경 사항을 확인합니다.
- 여러 컴포넌트가 얽혀 있으면 경계별 입력/출력을 확인합니다.
- 잘못된 값이 어디서 시작됐는지 역추적합니다.

### 2. 패턴 비교

- 같은 코드베이스의 정상 동작 예시를 찾습니다.
- 관련 문서와 기존 패턴을 확인합니다.
- 정상 예시와 실패 사례의 차이를 적습니다.

### 3. 가설 검증

- 가설을 하나만 세웁니다.
- 가장 작은 변경이나 로그로 가설을 확인합니다.
- 실패하면 같은 수정 위에 덧붙이지 않고 새 가설을 세웁니다.

### 4. 수정과 검증

- 원인을 재현하는 실패 테스트나 재현 절차를 만듭니다.
- 원인을 고치는 최소 수정만 합니다.
- 테스트/빌드/재현 절차로 해결 여부를 확인합니다.
- 같은 문제가 다시 생기지 않도록 `docs/troubleshooting/log.md`에 기록합니다.

## 중단 신호

아래 상황이면 바로 수정하지 않고 조사 단계로 돌아갑니다.

- 원인을 설명하지 못한 상태에서 고치려는 경우
- 여러 수정을 한 번에 넣으려는 경우
- 세 번 이상 수정했는데 계속 다른 문제가 나오는 경우
- "아마", "그럴 것 같음" 수준의 추측만 있는 경우

세 번 이상 수정이 실패하면 구조 자체가 맞는지 사용자와 논의합니다.
