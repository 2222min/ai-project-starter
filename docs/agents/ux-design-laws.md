# UX Design Laws

디자인, Figma 반영, UI 구현, 디자인 리뷰에서 참고하는 UX 법칙 체크리스트입니다.

목표는 법칙을 암기하는 것이 아니라, 화면의 판단 근거를 명확하게 만드는 것입니다.

## 적용 시점

- 기획 리뷰에서 사용자 흐름을 점검할 때
- 디자인 리뷰에서 UI/UX/일관성/기획정합성을 점검할 때
- Figma 노드와 코드 UI가 달라졌을 때
- 온보딩, 폼, 리스트, 검색, 결제, 완료 화면처럼 사용자의 판단이 중요한 화면을 만들 때
- 사용자가 "더 직관적으로", "쓰기 쉽게", "보기 좋게", "전환율 좋게" 같은 요청을 할 때

## 빠른 리뷰 질문

- 사용자가 한 화면에서 기억해야 할 정보가 너무 많지 않은가?
- 주요 행동이 첫눈에 보이는가?
- 선택지가 너무 많아 결정을 미루게 만들지 않는가?
- 익숙한 패턴을 깨야 한다면 이유가 충분한가?
- 터치/클릭 대상은 충분히 크고 가까운가?
- 400ms 안에 피드백이 있거나, 기다리는 이유를 알 수 있는가?
- 진행 상태와 완료 지점이 명확한가?
- 가장 중요한 순간과 마지막 순간이 긍정적으로 설계되어 있는가?
- 시각적 강조가 하나의 핵심 행동에 집중되어 있는가?
- 복잡성이 사용자에게 떠넘겨지지 않았는가?

## 인지와 지각

| 법칙 | 디자인 적용 |
|------|-------------|
| 심미적 사용성 효과 | 보기 좋은 UI는 더 쉽게 느껴진다. 단, 아름다움이 실제 사용성 문제를 가리지 않게 테스트한다. |
| 인지 편향 | 사용자는 기존 믿음과 경험에 기대어 판단한다. 확증 편향을 줄이려면 객관적 피드백과 비교 근거를 제공한다. |
| 인지 부하 | 불필요한 설명, 장식, 단계, 선택지를 줄인다. 핵심 정보와 행동만 우선 노출한다. |
| 선택적 주의 | 사용자의 목표와 관련된 정보와 행동을 가장 두드러지게 만든다. |
| 작업 기억 | 사용자가 기억해야 하는 값을 줄이고, 필요한 정보는 화면 안에 유지한다. |

## 의사결정

| 법칙 | 디자인 적용 |
|------|-------------|
| 선택 과부하 | 옵션이 많으면 추천, 필터, 그룹, 비교 표로 선택 범위를 좁힌다. |
| Hick의 법칙 | 중요한 결정일수록 선택지 수와 복잡도를 줄이고, 복잡한 작업은 단계로 나눈다. |
| 멘탈 모델 | 사용자가 이미 아는 패턴을 우선 사용한다. 새 모델이 필요하면 점진적으로 학습시킨다. |

## 피드백과 반응

| 법칙 | 디자인 적용 |
|------|-------------|
| Doherty 임계값 | 400ms 안에 반응을 제공한다. 느린 작업은 로딩, 진행률, 스켈레톤 등 체감 피드백을 제공한다. |
| Fitts의 법칙 | 주요 버튼은 충분히 크고, 자주 쓰는 행동은 손이 가기 쉬운 위치에 둔다. 버튼 사이 간격도 확보한다. |

## 몰입과 동기부여

| 법칙 | 디자인 적용 |
|------|-------------|
| 몰입 | 난이도와 사용자의 숙련도 균형을 맞춘다. 마찰을 줄이고 즉각적 피드백을 제공한다. |
| 목표 경사 효과 | 진행률, 단계 표시, 남은 작업 수를 보여 완료 동기를 만든다. |
| Zeigarnik 효과 | 저장 중, 이어하기, 완료 유도 장치로 미완료 작업을 다시 이어갈 수 있게 한다. |

## 정보 구조화

| 법칙 | 디자인 적용 |
|------|-------------|
| 청킹 | 정보를 의미 있는 묶음으로 나누고 제목, 구분선, 간격으로 구조를 드러낸다. |
| Miller의 법칙 | 7이라는 숫자를 고정 규칙으로 쓰지 않는다. 더 작은 그룹으로 나누는 근거로만 사용한다. |
| 순서 위치 효과 | 목록의 처음과 끝에 핵심 정보나 행동을 배치한다. |

## 게슈탈트 원칙

| 법칙 | 디자인 적용 |
|------|-------------|
| 공통 영역 | 같은 카드, 배경, 테두리 안의 요소는 하나의 그룹으로 인식된다. |
| 근접 | 가까운 요소는 관련 있다고 느껴진다. 관련 없는 요소는 간격을 둔다. |
| 간결성 | 복잡한 형태보다 단순하고 명확한 형태를 우선한다. |
| 유사성 | 같은 기능은 같은 시각 언어를 사용한다. 다른 기능은 충분히 구별한다. |
| 균일 연결 | 선, 색상, 프레임으로 연결된 요소는 강한 관계로 인식된다. |

## 사용자 행동 패턴

| 법칙 | 디자인 적용 |
|------|-------------|
| Jakob의 법칙 | 사용자는 익숙한 서비스의 패턴을 기대한다. 표준 패턴을 먼저 사용한다. |
| 능동적 사용자의 역설 | 사용자는 매뉴얼보다 바로 실행을 선호한다. 설명보다 인라인 힌트와 점진적 공개를 사용한다. |
| Peak-End 규칙 | 가장 강렬한 순간과 마지막 순간이 전체 경험 평가를 좌우한다. 성공/실패/완료 화면을 신경 쓴다. |
| Von Restorff 효과 | 중요한 행동 하나만 시각적으로 돋보이게 한다. 강조를 남발하지 않는다. |

## 설계 원칙

| 법칙 | 디자인 적용 |
|------|-------------|
| Tesler의 법칙 | 줄일 수 없는 복잡성은 시스템이 흡수하고, 사용자에게는 단순한 선택을 제공한다. |
| Postel의 법칙 | 입력은 유연하게 받아들이고, 출력은 일관되게 제공한다. |
| Occam의 면도날 | 같은 효과라면 더 단순한 구조를 선택한다. |
| 파레토 원칙 | 사용 빈도와 가치가 높은 20% 기능에 우선 집중한다. |
| Parkinson의 법칙 | 작업은 주어진 시간과 단계만큼 늘어난다. 범위와 완료 기준을 명확히 한다. |

## 디자인 리뷰 산출물에 남길 내용

필요한 경우 디자인 리뷰나 Figma 반영 기록에 아래 형식으로 남깁니다.

```markdown
## UX 법칙 검토

| 화면/흐름 | 관련 법칙 | 판단 | 조치 |
|-----------|-----------|------|------|
| 홈 화면 CTA | Von Restorff 효과, 선택적 주의 | 핵심 행동 강조 필요 | CTA 대비 강화 |
| 가입 폼 | 인지 부하, Hick의 법칙 | 입력 단계 과다 | 단계 분리 및 필수값 축소 |
```
