# Test and Verification

구현과 완료 보고는 검증 결과를 기준으로 합니다.

## 테스트 우선 원칙

기능 추가, 버그 수정, 리팩터링, 동작 변경에는 가능한 범위에서 테스트를 먼저 작성합니다.

권장 흐름:

1. 기대 동작을 보여주는 실패 테스트를 작성합니다.
2. 테스트가 기대한 이유로 실패하는지 확인합니다.
3. 통과에 필요한 최소 코드만 작성합니다.
4. 테스트가 통과하는지 확인합니다.
5. 중복 제거와 이름 정리만 수행합니다.
6. 전체 영향 범위의 테스트를 실행합니다.

## 예외

아래는 테스트 우선 원칙을 가볍게 적용할 수 있습니다.

- 문서만 수정
- 설정 파일만 수정
- throwaway prototype
- 테스트 환경이 아직 없는 초기 템플릿 상태
- 사용자가 명시적으로 테스트 생략을 요청한 경우

예외를 적용하면 최종 보고에 이유를 남깁니다.

## 완료 전 검증

완료, 수정됨, 통과, 문제 없음, 커밋 가능 같은 표현을 쓰기 전에 검증을 실행합니다.

검증 순서:

1. 어떤 명령이 이 주장을 증명하는지 정합니다.
2. 명령을 실행합니다.
3. 출력과 종료 코드를 확인합니다.
4. 성공이면 검증 결과를 함께 보고합니다.
5. 실패면 실제 상태와 남은 작업을 보고합니다.

## 자체 체크

- 새 동작을 검증하는 테스트나 대체 검증이 있는가?
- 실패해야 할 테스트가 실제로 실패하는 것을 봤는가?
- 테스트가 실제 코드 동작을 검증하는가?
- 전체 영향 범위에 맞는 검증을 실행했는가?
- 검증하지 않은 내용을 완료된 것처럼 말하지 않았는가?
